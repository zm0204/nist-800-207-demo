# SP 800-207A Mesh Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, following the user's request to implement and publish a PR.

**Goal:** Add a reproducible service identity demo alongside the working device gateway demo.
**Architecture:** Independent Kubernetes namespace and Istio sidecars. Optional gRPC ext_authz adapter delegates workload decisions to the existing PE, with Context audit.
**Tech Stack:** Python/FastAPI/httpx, Kubernetes, kind 0.33.0, Istio 1.31.1, Envoy v3 gRPC.
**Spec:** `docs/superpowers/specs/2026-10-15-207a-mesh-design.md`

## Global Constraints

- Preserve existing Compose, Passkey, PA sessions, device certificates and Dashboard behavior.
- Namespace `zta-207a`, trust domain `cluster.local`, dedicated cluster `zta-207a`.
- Default deny, STRICT mTLS, exact GET paths, no public application service.
- Missing policy, PE, audit, or adapter must fail closed.
- No end-user-per-hop or multi-cluster claim.

## Review Focus

- Forged identity headers cannot authorize a wrong workload (real mesh tests).
- Query strings cannot evade path policy; backend failure cannot become 200 (application tests).
- Missing/malformed workload policy or unavailable audit denies (PE tests).
- Envoy metadata without authenticated source/destination denies (adapter tests).
- Restoring an outage or policy recovers new traffic without weakening native ALLOW (mesh tests).
