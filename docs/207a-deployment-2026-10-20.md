叢集內的 probe、intruder、plaintext，而非瀏覽器 port-forward。

STRICT、default-deny、精確 principal/method/path ALLOW 與 backend CUSTOM policy 都已套用。

## 此 Windows 主機的操作指令

在 PowerShell 設定以下變數；工具已位於本專案旁的 `.tools`，Python 相依套件已裝入 `.venv`。
另一台主機請依 [完整部署指南](207a-mesh.md) 安裝相同版本工具，並把 `$kind`、`$istio` 改成對應路徑。

```powershell
$repo = 'C:\Users\user\.codex\.chatgpt-projects\g-p-6a93da7c3a3c81919224b886e5145181\zta-207a'
Set-Location -LiteralPath $repo
$python = Join-Path $repo '.venv\Scripts\python.exe'
$kind = Join-Path (Split-Path $repo -Parent) '.tools\kind.exe'
$istio = Join-Path (Split-Path $repo -Parent) '.tools\istioctl\istioctl.exe'
$config = Join-Path $repo '.tmp\mesh-kubeconfig'

# 查看目前已部署狀態
& $python scripts/mesh_demo.py --kind $kind --istioctl $istio --external-authz status

# 重新部署／更新同一個專用測試環境
& $python scripts/mesh_demo.py --kind $kind --istioctl $istio --external-authz up

# 重測：會短暫修改專用 namespace 的政策與 replicas
& $python scripts/mesh_demo.py --kind $kind --istioctl $istio --external-authz verify

# 單元與服務測試：專案內獨立暫存，避免受限執行環境的預設 Temp 權限問題
& $python -m pytest -q --basetemp=.tmp/pytest-manual
```

本次受限沙箱的預設 Temp 及子程序執行造成 pytest setup 卡住；改用主機權限與
專案內的獨立 basetemp 後，69 項測試於 3.35 秒內通過。無需修改應用程式。

若 18081 的背景轉送已停止，在新的 PowerShell 視窗先設定 `$repo` 和 `$config`，再執行：

```powershell
kubectl --kubeconfig $config --context kind-zta-207a -n zta-207a port-forward service/frontend 18081:8000 --address 127.0.0.1
```

保持視窗開啟；Ctrl+C 只停止轉送。若回報埠被占用，先檢查是否已有本次背景轉送；
其 PID 與日誌在 `.tmp/mesh-port-forward.pid`、`.tmp/mesh-port-forward*.log`，
不要終止不明程序。停止轉送不會停止 Kubernetes 工作負載。

若明確要永久刪除整個專用測試 cluster（包括 demo Secret 和 audit emptyDir）：

```powershell
& $python scripts/mesh_demo.py --kind $kind --istioctl $istio down
```
